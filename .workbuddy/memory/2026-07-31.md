### year/quarter 视图日期标签看不到（columnWidths 单位语义 bug）

- 用户反馈：切到 "年/季度" 后 timeline 完全看不到日期文本

- 默认值：day 30 / week 72 / month 34 / quarter 82 / year 120（每列像素）
- 注意：core 的 `defaultConfig.columnWidth = 30` 在 month 视图下也会得到 30 × 30 = 900px/月，同样是 bug，但当前未被触发（因为 demo 用了 columnWidths 覆盖）

### 列宽自适应屏幕（修复"挤一坨"）

- 用户反馈：100 条数据 + month/quarter 视图下，甘特条全挤在左侧，timeline 大部分空白
- 数据特点：100 条跨度 ~36 天、1000 条 ~60 天、3200+ 条 ~72 天（`createLargeDataset` 的 `group % 40` 限制了跨度上限）
- 解决： playground 层加自适应逻辑 `applyAdaptiveColumnWidth()`，根据 `spanDays` + `viewportWidth` 动态算 columnWidth
- 核心公式：`columnWidth = max(lowerBound, min(ideal, range.max))`
  - `lowerBound = max(range.min, viewportWidth / spanDays)` —— 至少填满视口
  - `ideal = 1.2 × viewportWidth / spanDays` —— 目标 1.2 倍视口留滚动余地
  - `range` = 每个 viewMode 的"每天像素" min/max（month 0.6-30、quarter 0.2-10、year 0.05-2.5、day 22-60、week 4-20）
- 触发时机：useDemoDataset / setDemoViewMode / window resize（debounce 150ms）/ onMounted 初始化
- 视口宽度测量：优先 `document.querySelector(".gantt-demo-hero .gantt-timeline").clientWidth`，fallback 用 window 估算
- 实现位置：playground/src/App.vue，demoColumnWidths 对象按 viewMode 动态更新，通过替换 columnWidths 引用触发响应式
- 验证：core 7 tests + vue-gantt 50 tests 全过

## 引擎层重构 · 阶段3 第一小步：止血拖动松手"右侧格子乱"bug + engine 接管 scrollLeft 边界

- bug 根因（精确定位）：拖动松手 onUp 清 `dragPreview.value = null` → dateRange computed 收缩（不再含 preview 日期）→ totalWidth 变小 → 但 `scrollLeft` 没跟着 clamp 到新的 `maxScrollLeft = scrollWidth - clientWidth` → canvas 的 `transform: translate(scrollLeft)` 超出 timeline-inner 内容区 → 而 scale 的 ticks 不覆盖那么远 → 右侧出现"没绘制完的格子"+页面不同步。用户截图的"中间起始滚动条"也是 scrollLeft 残留非零导致。
- 修复（最小侵入，不迁渲染）：
  - `GanttEngine` 加 `clampScrollLeft()`：读 container.scrollWidth/clientWidth 算 max，scrollLeft>max 则写回 max。视口边界管理权归引擎。
  - `GanttChart.vue` 加 `finishDragRender()`：调 `engineRef.value?.clampScrollLeft()` + 同步 `scrollLeft.value = timeline.scrollLeft` + `nextTick(drawCanvas)`。
  - 加 `watch(dragPreview, next => { if (!next) finishDragRender() })`——dragPreview 变 null 时（松手/取消/无 delta 三条路径统一）触发，覆盖 beginDrag + beginPlanDrag 共 7 处 dragPreview=null，无需逐处改。
- 关键设计：用 watch(dragPreview) 而非逐处 patch，一处覆盖所有清空路径；clamp 逻辑放 engine（成熟做法：视口边界是引擎职责），组件只触发 + 重绘。
- 补测试：GanttEngine.test.ts 视口组加 `clampScrollLeft 把超界 scrollLeft 限制到 maxScrollLeft`（超界→max、未超界不动）。
- 验证：core build✓ + 35 tests✓（28 engine 含新 clamp 测试 + 7 core）；vue-gantt typecheck✓ + 50 tests✓（零回归）+ build✓；playground typecheck✓ + build✓。
- 同步：新 dist 复制到 D:\myWork\2\ct-gantt-{core,vue}。
- 诚实说明：这是止血（dragPreview 清空后的 clamp+重绘），不是根治——完整根治需继续把 dateRange/scale/dragPreview 状态迁进 engine 成为单一数据源（多回合）。本回合让 bug 不再复现，且 engine 接管了 scrollLeft 边界。

## 双击依赖线无法编辑 bug 修复（CSS z-index）

- 用户反馈：双击依赖线无反应、无 console 输出。多轮诊断（加 alert/console.log/linkOverlayItems log/timeline @click.capture log）。
- 根因：`.gantt-link-layer` z-index:2 与 `.gantt-timeline-row` z-index:2 同层，按 DOM 顺序 bars/row（后）盖住 link-layer（前）。row 有 `@click.stop="selectedTaskId=..."` 全宽拦截 click，link-hit polyline（pointer-events:stroke）永远收不到 click → openLinkEditor 不触发。
- 诊断关键：timeline @click.capture log 显示 click target 全是 `DIV gantt-timeline-row` / `BUTTON gantt-link-handle`，从无 `gantt-link-hit`；linkOverlayItems log 显示 5 items 渲染（虚拟滚动 layoutById 只 20，13 条 link 被 skip，但 5 条渲染的也点不中——因 row 覆盖）。
- 修复：`.gantt-link-layer` z-index 2→3（gantt.css:642），高于 row z2，依赖线 hit polyline 在 row 上方可点。
- 验证：用户确认双击依赖线 alert 弹（openLinkEditor 触发）→ 编辑成功。
- 性质：**不是 engine 接入引入**（git diff 确认 gantt.css/link 代码这几天没改）。是 CSS 层级潜在 bug，engine 重构期间诊断才暴露。之前可能没触发（虚拟滚动窗口/row 覆盖范围不同时）。
- 清理：移除所有诊断代码（alert/console.log/linkOverlayItems log/timeline @click.capture/logTimelineClick），rebuild 干净版（dist 0 处 gantt-debug）。
- 验证：vue-gantt build✓ + 50 tests✓；playground build✓。dist 同步 D:\myWork/2。
- 教训：click 不触发的排查链——先加 handler 首行 alert（绕开 console 静默/缓存/端口问题）确认函数是否触发；不触发则加容器 @click.capture log 看 click target；target 是别的元素 = CSS 层级覆盖（z-index + DOM 顺序 + pointer-events）。
